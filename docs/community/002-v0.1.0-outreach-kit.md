# v0.1.0 Tester Outreach Kit

Status: active
Updated: 2026-05-31
Tester issue: https://github.com/Eskasia/smart-contract-security-assistant/issues/12
Tester guide: `docs/community/001-v0.1.0-tester-feedback.md`

## Goal

Invite Solidity/Web3 users to run the v0.1.0 quickstart and leave public,
reproducible feedback in issue #12.

## Target Testers

Prioritize people who can give useful setup and report feedback:

- Solidity developers who have Python and `solc` available.
- Smart contract audit learners.
- Web3 hackathon builders.
- OSS maintainers reviewing Solidity pull requests.

Avoid asking people to test private, proprietary, or third-party contracts
without permission.

## Short Message

```text
Hi, I am collecting quickstart feedback for Smart Contract Security Assistant v0.1.0, a local-first Solidity security triage tool.

Could you run the clean-clone quickstart and leave your result in this GitHub issue?

https://github.com/Eskasia/smart-contract-security-assistant/issues/12

It should take about 5-10 minutes if Python, uv, solc, and Slither install cleanly. Please only test contracts you own or are authorized to review, and do not share private keys, secrets, proprietary contracts, or customer audit material.
```

## Technical Message

```text
I am looking for 3 independent tester reports for Smart Contract Security Assistant v0.1.0:

Release:
https://github.com/Eskasia/smart-contract-security-assistant/releases/tag/v0.1.0

Tester issue:
https://github.com/Eskasia/smart-contract-security-assistant/issues/12

Quickstart:
git clone https://github.com/Eskasia/smart-contract-security-assistant.git
cd smart-contract-security-assistant
uv sync --extra audit --dev
uv run scsa analyze tests/contracts/VulnerableVault.sol --out-dir reports-demo
uv run pytest

Expected:
- overall_status: finding
- f_001: reentrancy
- severity: 3
- pytest: 15 passed

The tool is for first-pass local triage and human review, not a full audit replacement. Please only share public-safe summaries.
```

## Evidence Rules

Useful evidence:

- Public issue comments on #12 with environment, commands, result, and feedback.
- Public posts linking to the release or quickstart issue.
- Public forks/stars from actual testers.
- Public external project references using `v0.1.0`.

Not enough by itself:

- Private chat saying "looks good".
- Self-run local output.
- Stars from accounts that did not run or inspect the project.
- Comments that do not mention environment, command result, or feedback.

## Maintainer Follow-Up

For every tester response:

1. Thank the tester.
2. Label or link any actionable bug/feature follow-up.
3. Update `docs/community/003-v0.1.0-feedback-tracker.md`.
4. Keep private or unsafe contract details out of public issues.
