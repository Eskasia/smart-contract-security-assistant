# v0.1.0 Release Readiness Checklist

Status: ready for tag
Updated: 2026-05-31
Milestone: https://github.com/Eskasia/smart-contract-security-assistant/milestone/1
Tracking issue: https://github.com/Eskasia/smart-contract-security-assistant/issues/8

## Release Goal

Publish the first public OSS release of Smart Contract Security Assistant as a
local-first Solidity security triage tool with clear scope, reproducible
validation, and explicit authorized-use boundaries.

## In Scope for v0.1.0

- CLI analysis for a single Solidity entry file.
- Slither-backed deterministic findings.
- Normalized JSON and Markdown reports.
- SQLite trace output for review and debugging.
- Local RAG context and deterministic fallback explanations.
- MLX-ready local generation path when a compatible runtime/model exists.
- README quickstart using `tests/contracts/VulnerableVault.sol`.
- OSS readiness files: license, contribution guide, security policy, conduct
  policy, issue templates, and pull request template.

## Deferred Follow-Up Scope

- Source import and API hardening: issue #4.
- Frontend audit workbench: issue #5.
- Report export and trace review workflow: issue #6.
- Public benchmark and project build gates: issue #7.

These items should not block v0.1.0 unless they are split into focused PRs,
reviewed, and merged with their own validation evidence.

## Release Notes Must Include

- Current scope and input limits.
- Authorized-use boundary.
- Human-review-required caveat.
- Known limitations.
- Validation commands and observed results.
- Links to follow-up issues #4 through #8.

## GitHub Release Steps

1. Confirm `main` is up to date and CI is passing.
2. Update `CHANGELOG.md` from `Unreleased` to `v0.1.0` with the release date.
3. Commit the changelog update through a pull request.
4. Tag the merge commit:

   ```bash
   git tag v0.1.0
   git push origin v0.1.0
   ```

5. Create the GitHub release from the tag.
6. Paste release notes from the changelog and this checklist.
7. Re-check the README quickstart after the release page is live.

## Do Not Include

- Generated report folders unless explicitly required for a release artifact.
- Private keys, secrets, customer data, proprietary contracts, or unpublished
  third-party audit material.
- Claims that the tool replaces manual audit.
- Unreviewed source-import, frontend, benchmark, or hackathon changes from the
  closed PR #1 bundle.
